# KAC 출도착 GW 연동

## 근거와 범위

2026-09-29 [공식 서비스 15158625](https://www.data.go.kr/data/15158625/openapi.do)의
내장 Swagger와 설명을 확인했다. KAC 출도착은 HTTPS `B551178/flight-status/depart`와
`/arrival`을 사용한다. 주차·요금·IIAC·기존 ODCloud raw 메서드는 변경하지 않는다.

공식 명세는 `pageNo`, `numOfRows`, `totalCount`를 문자열로 설명하지만 응답 필수 목록이나
페이지 크기 상한/기본값을 확정하지 않는다. 시각 필터 생략이 하루 전체를 뜻하는지, 페이지가
동일 시점 스냅샷인지도 보장하지 않는다. 따라서 이 라이브러리의 검증 정책과 공식 보장을
구별한다. `estimateddatetime`의 공식 설명은 실제시간이며 기존 `estimated_at`에 보존한다.

## SDK 품질·호출 정책

- 기존 `departures`/`arrivals`는 한 페이지 `list[Flight]` 계약을 유지한다.
  성공 header/body를 확인하며 공통 GW 오류 envelope를 빈 목록으로 반환하지 않는다.
  인증/쿼터 오류는 공통 예외로 분류하고 항공편 파싱 오류의 원시 값·원인 traceback은 숨긴다.
- `KacClient.flight_status(airport_code, searchday, num_of_rows=100, max_pages=20)`은
  두 방향의 제공 범위를 모두 읽은 뒤 반환한다. 통합 클라이언트의 `client.kac`로 접근한다.
- `searchday`는 유효한 YYYYMMDD, 크기는 1~1000, 논리 페이지 예산은 2~100으로 제한한다.
  이는 SDK 안전 상한이지 제공기관이 해당 크기를 지원한다는 보장이 아니다.
- 명시적 성공 header와 양의 페이지/크기, 음수가 아닌 총건수, 항목 수를 검증한다.
  첫 응답에서 서버가 축소한 크기는 수용하지만 이후 크기/총건수 변경은 오류다.
- 편명/예정시각 누락, 페이지 반복, 중간 빈 페이지, 상한 소진 시 부분 성공을 반환하지 않는다.
  필드 필수성은 SDK 품질 정책이며 Swagger의 필수 선언이 아니다. 오류 메시지에 row를 넣지 않는다.
- `max_pages`는 두 방향을 합한 논리 요청 상한이다. HTTP 재시도는 별도이므로 엄격한
  호출 상한이 필요한 소비자는 `retries=0`을 쓴다. 공통 TPS 예산은 계속 적용한다.
- 원본 `fid`, `masterflightid`와 코드셰어를 보존하며 편명만으로 임의 병합하지 않는다.
  `fid`가 있으면 예정시각 변경과 무관하게 같은 방향 내 반복을 검출한다.
  날짜만 있는 예정/변경 시각은 자정으로 만들어내지 않고 거부한다.
  `flightid`, `arrvAirportCode`를 정규화하고 공항명·노선 구분은 선택 모델 필드로 제공한다.

## 검증과 운영 상태

모의 XML로 축소된 페이지, 두 방향, 식별자 문자열, 시간대, 잘못된 메타데이터, 반복 페이지,
403 재시도 금지 등을 검증한다. 운영 키의 후속 단일 요청은 HTTP 403·GW 코드 30이다.
승인·키 연결 상태를 사용자에게 확인 요청했다. **live 성공을 주장하지 않는다.**
승인 상태 확인 뒤 제한된 opt-in 테스트가 필요하다. 정상 서비스 여부 확인 전 머지/배포하지 않는다.

2026-09-29 WSL 오프라인 전체 147개·하위 검증 14개 통과, live 3개 제외, 커버리지
92.02%다. Ruff·mypy(22파일)·compileall 및 SKILL 검증도 통과했다. 최초 전체 실행의
구 endpoint 기대와 새 선택 필드 snapshot 2건은 명시적 계약 변경에 맞춰 갱신했다.
James/Popper 리뷰 지적을 추가 회귀 13개 실패로 확인한 뒤 수정했다. 전체 162개·하위 14개
통과, live 3개 제외, 커버리지 92.15%, Ruff·mypy·compileall 통과. 재리뷰/최종 CI는 대기 중이다.
소비자의 Async 이름 제거 대응 및
새 typed 조회 연동도 별도 작업이며, 라이브러리 코드만으로 운영을 수정했다고 주장하지 않는다.
